# Dead Space Reanimated — comparative reverse-engineering reference

**Checked:** 2026-11-02  
**Upstream:** https://github.com/GINESTR0/DeadSpaceReanimated  
**Verified upstream main tree:** `89fd28abd` (2026-10-08)  
**Our target:** true native x86-64 Windows/Linux port, asset-free binaries, user-owned original APK.

## What upstream actually publishes

The upstream Git tree contains **only `README.md` and five screenshots**;
there are no public engine sources, build files, native runtime sources, patch
diffs or reusable asset-decoder implementations.

Two GitHub releases (`v1.2`, `v1.3`) contain an approximately **715 MB APK**
(`DeadSpaceReanimated-1.3.apk` is 715,366,829 bytes). Both release APKs have
**exactly the same byte length but different GitHub SHA-256 digests**:
- v1.2: `042c0d60c53c72d3c71137710834f2081684625d66d0c3d214d9e75d468830a3`
- v1.3: `dbd94ee54fc3fefdddb101fac4eba1e2058a5db7cfcf30ac41ad96e88b285a3a`

Therefore these are distinct APK contents, even though their file sizes match.
The source-code ZIPs auto-generated by GitHub only contain the README and
screenshots. The GitHub API reports **no declared project license**.

Upstream describes its app as a 64-bit Android shell that **dynamically
translates the original game's ARM32 instructions** and provides replacements
for graphics, sound, motion, storage and lifecycle. This is not a native
C++ reimplementation of the Dead Space Mobile game engine. The README
*claims* the 2011 engine and logic are unmodified; that claim has **not**
been independently proved against our user's original `libEAMGameDeadSpace.so`.

**Do not copy its bundled copyrighted APK, remastered textures, binaries or
unlicensed code** into this repository. Credit Ginestro when referring to
her published observations. Her binary/runtime architecture contradicts
this port's non-emulated x86-64 design.

## The binary comparison that could reveal real implementation clues

The Reanimated APK is about 715 MB; our existing known original/Fixes
APK is 325,769,461 bytes. **The file-size difference proves nothing about
game-code differences**: modded textures and runtime data can account for
growth. **Real-APK GitHub Actions comparison 41432386853 has now proved**
that the original ARM ELF `lib/armeabi/libDeadSpace.so` is byte-identical
to Reanimated's `assets/game/libDeadSpace32.so`: both are 6,672,749 bytes
and SHA-256 `2fc87e9a5afa1028d91a9770d23ffd04b45fb5dbc8d3800ed6b31e34223a490b`.
Reanimated additionally ships its separate AArch64
`lib/arm64-v8a/libdsr.so` (4,415,408 bytes). **These native libraries
are not source code**. Exact original game logic identity is established
for the matched ARM ELF; altered behavior may be in the new runtime.

The first comparison found zero identical original asset paths between
the 1,731 original and 1,955 reference assets. This **does not** imply
all original asset data changed: the remaster reorganized its assets.
A follow-up compares asset length/CRC32 signatures across renamed paths
without exporting any game data.

On an isolated machine or **ephemeral GitHub runner**, with both APKs
obtained legally by the tester, execute our existing metadata inventory
tool for each (not in a public artifact):

```sh
python tools/deadspace_audit.py --root . --apk /private/original.apk \
  --output /private/original-audit.json
python tools/deadspace_audit.py --root . --apk /private/reanimated.apk \
  --output /private/reanimated-audit.json
```

Compare JSON fields: `native_libraries[].apk_path`, `sha256`,
`machine`, `elf_class`, `needed_libraries`, `bootstrap_exports`,
`platform_api_import_evidence`, and aggregated `entry_groups`.
A matching ARM ELF SHA256 would establish **byte-identical game code** in
the matched file; differing SHA256 means more inspection is needed, not
proof of a different game engine. An embedded payload outside `lib/`
may be invisible to this existing auditor; do not infer the game's ARM
payload is absent solely because library lists differ.

If there are enough matching names to justify deeper work, compare
**only ZIP central-directory asset file metadata** (paths, sizes, CRC32)
then selectively compare SHA256 of specific *locally held* original assets.
Never post game bytes, rebuilt sounds or textures. Do not assume that
Reanimated's optional modified textures can be parsed by our current
original `IM`/`M3G` decoders without tests.

## Integration decisions

1. **Immediate:** retain original-native Windows/Linux architecture;
   do not integrate upstream dynamic ARM translator.
2. **Verification:** record actual main-menu→profile→game→zero-G behavior
   on user's device if available; create screenshots/measurements without
   redistributing the original APK.
3. **Next engine boundary:** continue our original resource receiver,
   allocator and startup code from the original APK, not the Reanimated README.
4. **Post-boot optional enhancements:** resolution-scaling and sampler
   quality options, correct laser/reticle accessibility, SFX priority and
   animation-synced reload audio; keep faithful baseline distinct from mods.
5. **Verified:** original ARM ELF identity across both released APKs (SHA-256).
   **Still unverified:** reference game's actual HD asset byte compatibility,
   any unpublished runtime source or internal renderer patch code,
   and reproducibility of 60 FPS on low-end hardware.

No original game data or third-party binary has been copied by this audit.
