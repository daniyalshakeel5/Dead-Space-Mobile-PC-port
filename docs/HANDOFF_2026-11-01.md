### Native IronMonkey geometry milestone

After verifying all 4,154 Mesh→VertexBuffer and 4,165 VertexBuffer→VertexArray references, 10,078 exact VertexArray byte sizes, 4,431 IndexBuffer→TriangleStripArray/Appearance links, 4,362 Mesh→proprietary IndexBuffer references, and 4,362 three-index strips with bounds-safe indices:

- Added `include/ds_port/im_mesh.hpp`, `src/im_mesh.cpp`, `apps/im_mesh_extract.cpp`, and `tests/im_mesh_tests.cpp`.
- **37/91 IM-M3G resources** passed the new native C++ geometry decoder.
- Aggregate decoded geometry across those 37 resources: **4,154 Mesh objects, 4,362 submeshes, 546,488 vertices, 398,634 triangles**.
- Three local OBJ conversions on ephemeral GitHub runner storage passed basic OBJ vertex/face/index-count checks, then were deleted; no copyrighted OBJ model was uploaded.
- The output currently contains triangle positions only. It omits UV coordinates, normals, materials, skin weights/bones, animation, scene transforms and texture bindings. **No visual quality/winding proof**.

[Native actual-APK mesh verification](https://github.com/daniyalshakeel5/Dead-Space-Mobile-PC-port/actions/runs/41292859630).

## Local use of the new independently written native tools

The user must provide the original APK locally; the Windows/Linux CI binaries contain **no game content**. After installing the APK's `assets/` with `ds_asset_install`, use these programs on extracted local files:

```sh
ds_m3g_probe "<your local texture.m3g>" --decode-image
ds_m3g_texture_extract "<your local texture.m3g>" "<new output.png>"
ds_im_mesh_extract "<your local model.m3g>"                 # counts-only mode
ds_im_mesh_extract "<your local model.m3g>" "<new output.obj>"
```

`ds_im_mesh_extract` supports the verified simple position/triangle-list subset, not all 91 model resources. Even a valid OBJ can have incorrect winding, orientation or missing textures without full loader verification. No original data is included in the utilities.
